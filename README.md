# Аллокация сотрудников по проектам

Сервис для ежемесячного учета, на какие проекты работают сотрудники, и расчета расходов на них.

**Что он делает**

1. **Принимает аллокацию** (доли времени сотрудника по проектам) из Excel или через веб-форму.
2. **Сверяет ее с Jira:** если у человека указан проект, а задач по нему в Jira нет, случай уходит на ручной разбор.
3. **Загружает выгрузки 1С** (штатные, зарплата, налоги и взносы, НДФЛ, карточка счета 51) и по правилам бухгалтерии считает **расходы по проектам** за месяц (начисления и оплаты).
4. **Хранит историю по месяцам**, закрывает месяц от правок и ведет журнал изменений.

Данные содержат персональную информацию и зарплаты, поэтому доступ к ним должен быть только у тех, кому он положен (см. раздел «Безопасность»).

## Запуск в Docker

Нужен только Docker. Образ содержит веб-форму и все командные задачи.

```sh
docker build -t allocation .
```

Данные лежат в одной папке на сервере, например `work/`, которая монтируется в контейнер как `/data`:

```
work/
├── data/                       входные файлы (кладете вы)
│   ├── allocation.xlsx         аллокация из Excel (имя любое)
│   └── 1c/                     шесть выгрузок 1С за месяц, имена файлов не важны
├── config/                     справочники (необязательно)
│   ├── employees.csv           сотрудники из 1С: employee_id;name;jira_login;...
│   ├── jira_project_map.csv    ключи проектов Jira -> проекты аллокации
│   └── headcount_exclude.txt   ФИО, которых не считать в количестве людей
└── out/                        результаты (создаются сами)
```

Права на папку: контейнер пишет в нее от имени пользователя, которого вы укажете. Проще всего запускать под своим пользователем: `--user "$(id -u):$(id -g)"`.

### Командные задачи

Шаблон: `docker run --rm --user "$(id -u):$(id -g)" -v "$PWD/work:/data" allocation <команда> [параметры]`

```sh
# 1. аллокация из Excel в базу
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD/work:/data" allocation import-allocation data/allocation.xlsx

# 2. выгрузки 1С за месяц
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD/work:/data" allocation import-1c --month 2026-09 --dir data/1c

# 3. расходы по проектам
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD/work:/data" allocation cost-report --month 2026-09
```

Результат: `work/out/costs/projects-2026-09.xlsx` (итог по проектам) и `projects-2026-09-notes.md` (замечания). Справка по любой команде: `allocation <команда> --help`, список команд: `allocation help`.

### Веб-форма ввода аллокации

```sh
cp .env.example .env        # заполните WEB_USER, WEB_PASSWORD, WEB_SECRET
mkdir -p work && docker compose up -d --build
```

Форма доступна на `http://127.0.0.1:8000`. Наружу ее открывает обратный прокси с HTTPS (см. `docs/deploy.md`). Без заданного входа контейнер откажется стартовать на сетевом адресе. Подробнее: `docs/usage.md`, раздел «Веб-интерфейс».

## Внешние параметры

Все настройки передаются переменными окружения (файл `.env`, `-e` у `docker run` или секреты оркестратора). Токены и пароли в образ и в репозиторий не попадают.

| Переменная | Нужна для | Описание |
|---|---|---|
| `WEB_USER`, `WEB_PASSWORD` | веб-форма | Общий логин и пароль входа. Обязательны, если форма доступна по сети |
| `WEB_USER_HEADER` | веб-форма | Вместо пары выше: имя заголовка, в котором прокси с единым входом передает пользователя (например `X-Forwarded-User`). Имя попадает в журнал |
| `WEB_SECRET` | веб-форма | Длинная случайная строка для подписи сообщений формы |
| `WEB_HOST`, `WEB_PORT` | веб-форма | Адрес и порт, по умолчанию `0.0.0.0` и `8000` |
| `WEB_ALLOW_ANONYMOUS` | веб-форма | `1` разрешает запуск без входа (только если доступ закрыт снаружи) |
| `JIRA_URL` | check-jira, reconcile, sync-jira | Адрес Jira, например `https://jira.example.com` |
| `JIRA_TOKEN` | то же | Персональный токен (PAT) служебной учетной записи с правом чтения |
| `JIRA_USER`, `JIRA_PASSWORD` | то же | Вместо токена, для старых версий Jira |
| `JIRA_CA_BUNDLE` | то же | Путь к сертификату внутреннего удостоверяющего центра (файл внутри `/data`) |
| `ALLOC_DB`, `ALLOC_ROSTER`, `ALLOC_PROJECT_MAP`, `ALLOC_JIRA_DIR` | веб-форма | Пути внутри контейнера, по умолчанию `out/allocation.sqlite`, `config/employees.csv`, `config/jira_project_map.csv`, `out/jira` |

Для задач из таблицы Jira нужен сетевой доступ контейнера к серверу Jira (внутренняя сеть или VPN).

## Как передать файл для анализа

Положите файлы в `work/data/` и укажите путь внутри контейнера (относительно `/data`):

- **Аллокация:** `allocation import-allocation data/allocation.xlsx`. Блоки по месяцам в одном листе, шапка с названиями проектов, строки сотрудников с долями.
- **Выгрузки 1С:** все шесть файлов (xlsx или xls) одной папкой, `allocation import-1c --month ГГГГ-ММ --dir data/1c`. Какой файл какой отчет, скрипт определяет по заголовку внутри файла, поэтому имена любые. Нужны отчеты за месяц расчета и «Налоги и взносы» за предыдущий месяц.

## Что делает каждая команда

| Команда | Что на входе | Что делает | Что на выходе |
|---|---|---|---|
| `import-allocation <файл.xlsx>` | Excel с ручной аллокацией по месяцам | Читает, проверяет суммы долей, дубли и названия, загружает в базу | `out/allocation.sqlite`, `out/report.md` с номерами строк для правки |
| `import-1c --month --dir` | шесть выгрузок 1С | Разбирает по сотрудникам: оклад, начислено, взносы, оплачено, НДФЛ. Сверяет с итогами отчетов | `out/costs.sqlite` (зарплаты, права 600), `out/costs/costs-load-ГГГГ-ММ.md` |
| `cost-report --month` | обе базы | Умножает расходы на доли и суммирует по проектам | `out/costs/projects-ГГГГ-ММ.xlsx`, `...-notes.md` |
| `reconcile --month` | аллокация, список сотрудников, данные Jira | Находит доли без задач в Jira | `out/reconcile/review-ГГГГ-ММ.csv`, `report-ГГГГ-ММ.md` |
| `check-jira` | `JIRA_URL` и токен | Проверяет доступ и наличие задач, выводит только количества | текст в консоль |
| `sync-jira` | список сотрудников, часы Jira | Считает доли из списанных часов (если время в Jira ведут) | база и отчет |
| `web` | база аллокации | Веб-форма ввода и закрытия месяца | сервис на порту 8000 |

## Безопасность

- **Персональные данные и зарплаты.** База расходов `out/costs.sqlite` и Excel с расходами создаются с правами 600. Держите `work/` на закрытом томе и ограничьте доступ.
- **Данные в образ и репозиторий не попадают:** папки `data`, `out`, `config`, `work`, файлы `.env`, `*.xlsx`, `*.sqlite` исключены в `.gitignore` и `.dockerignore`.
- **Вход.** Веб-форма без входа по сети не запускается. Для нескольких пользователей используйте прокси с единым входом и `WEB_USER_HEADER`.
- **Закрытый месяц** не перезаписывается ни из веба, ни импортом из Excel. После правок в вебе импорт откажется пересоздавать базу.
- Контейнер работает без прав root. Проверка сертификата Jira не отключается: для внутреннего центра передайте файл в `JIRA_CA_BUNDLE`.

## Запуск без Docker и разработка

Нужен Python 3.10+.

```sh
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python -m unittest discover -s tests          # тесты
python web_app.py                             # веб-форма на http://127.0.0.1:8000
```

Подробная инструкция по скриптам (macOS, правила разбора, формат справочников): [`docs/usage.md`](docs/usage.md).
Развертывание на сервере, GitLab, запрос учетных записей: [`docs/deploy.md`](docs/deploy.md).
