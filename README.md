# Аллокация сотрудников по проектам

Аллокацию формирует руководитель вручную по форме (Excel). Часы в Jira не ведутся, поэтому Jira используется для
контроля: проверяем, что по каждому проекту из аллокации у человека есть задачи. Сотрудников берем из 1С.
Сценарии:

0. **Расходы по проектам** (`onec_import.py` и `cost_report.py`): выгрузки 1С по зарплате умножаются на доли аллокации, на выходе Excel с суммами по проектам.
1. **Перенос аллокации из Excel** (`allocation_import.py`): читает ручной файл, проверяет его и грузит в базу.
2. **Сверка с Jira** (`reconcile_jira.py`): находит людей, у которых в аллокации указан проект, а задач по нему в Jira нет, и отдает их на ручной разбор.
3. **Расчет долей из часов** (`sync_jira.py`): работает, только если в Jira ведут списания времени. Сейчас не используется.

## Расходы по проектам

Правила расчета описаны в ТЗ бухгалтерии (лист «Лист3», блок «распределение по проектам»). Расходы каждого сотрудника умножаются на его доли по проектам и суммируются по проектам.

**Шаг 1. Загрузить выгрузки 1С** (xlsx или xls) за месяц расчета, например сентябрь:

    python onec_import.py --month 2026-09 --staff "Штатные сотрудники.xlsx" --payroll "Анализ зарплаты.xlsx" \
        --taxes "Налоги и взносы сент.xlsx" --taxes-prev "Налоги и взносы авг.xlsx" \
        --ndfl "Анализ НДФЛ.xlsx" --card51 "Карточка 51.xls"

| Что считается | Отчет 1С | Столбец |
|---|---|---|
| должность, подразделение, количество ставок, оклад на ставку | Штатные сотрудники | Должность, Количество ставок, Оклад, районный коэффициент, северная надбавка |
| начислено | Анализ зарплаты по сотрудникам (помесячно) | Всего начислено |
| страховые начислено | Налоги и взносы (кратко) за месяц расчета | Единый тариф + Несч. случаи |
| оплачено | Карточка счета 51, статья «Оклады» | сумма по кредиту, суммируется по ФИО |
| НДФЛ | Анализ НДФЛ по месяцам | Исчислено налога (секция месяца расчета, другие секции через `--ndfl-months`) |
| страховые оплаченные | Налоги и взносы (кратко) за предыдущий месяц | Единый тариф + Несч. случаи |

Столбцы ищутся по названиям в шапке, а не по буквам. Оклад на ставку считается как оклад × районный коэффициент + оклад × северная надбавка / 100. Количество ставок вида `2/5` переводится в число. Строки подразделений и итоговые строки пропускаются. Сумма по сотрудникам сверяется с итоговой строкой отчета, расхождение попадает в предупреждения. Месяц отчета проверяется по его заголовку. Люди, у которых есть деньги в отчетах, но нет места в штатном списке (уволенные, договоры), сохраняются и подсвечиваются.

**Шаг 2. Посчитать расходы по проектам:**

    python cost_report.py --month 2026-09 --headcount-exclude "Иванов Иван Иванович"

Результат `out/costs/projects-ГГГГ-ММ.xlsx`: по каждому проекту оклады, страховые и итог по начислению, оклады, НДФЛ и страховые по оплате, количество людей и ставок. Колонка «Не распределено» собирает расходы людей без аллокации и остаток при сумме долей меньше 1, чтобы итог сходился с общими расходами. Количество людей и ставки считаются только по тем, кто есть в 1С, внешние исполнители выводятся отдельной строкой. Список `--headcount-exclude` (или файл `config/headcount_exclude.txt`) убирает людей из количества, но не из расходов и не из ставок, как в ТЗ. Замечания к расчету пишутся в `projects-ГГГГ-ММ-notes.md`.

Строки по сотрудникам с зарплатами в Excel не попадают. Они добавляются только ключом `--detail`.

**Доступ.** Зарплаты хранятся в `out/costs.sqlite`, отдельно от аллокации (`out/allocation.sqlite`). Файл доступен только владельцу (права 600). Запускать эти два шага должен тот, у кого есть доступ к финансовым данным. Остальным достаточно сводки по проектам. Файлы xlsx, sqlite и каталог `out/` в репозиторий не попадают.

## Сверка аллокации с Jira

Правило: если у человека за месяц указан проект (например, 10%), а в Jira у него по этому проекту нет задач, случай подсвечивается и уходит на ручной разбор. Ничего не исправляется само.

Порядок: сначала загрузите аллокацию за месяц (`python allocation_import.py data/allocation.xlsx`), затем запустите сверку.

    python reconcile_jira.py --month 2026-09

Что нужно: аллокация за месяц в базе (из Excel или из `sync_jira.py`), `config/employees.csv` из 1С и `config/jira_project_map.csv`, где `raw_name` это ключ проекта Jira, а `project` название проекта в аллокации (проекты без записи в справочнике не проверяются).

Активностью считается задача в проекте, где человек исполнитель и которая обновлялась в этом месяце. Если когда-нибудь начнут списывать время, добавьте `--with-worklogs`, и списания тоже будут считаться активностью. Мелкие доли можно не проверять: `--min-share 0.05`. Запускайте сверку в первые дни следующего месяца: задачи, обновленные позже, исказят картину.

Ограничение: если задачу передали другому исполнителю, у прежнего она из активности пропадает. Поэтому результат это повод посмотреть, а не вердикт.

Без доступа к Jira: `--save-assignments файл.csv` сохраняет полученные задачи, а `--assignments-csv файл.csv` позволяет прогнать сверку по ним повторно.

Результат в `out/reconcile/`:

- `review-ГГГГ-ММ.csv` список на ручной разбор: сотрудник, проект, доля, ключи Jira, где человек работал вместо этого, и пустой столбец `decision` для решения;
- `report-ГГГГ-ММ.md` итоги, а также строки, которые проверить не удалось: нет сотрудника или логина Jira в списке 1С, проект не связан с Jira.

Если в списке сотрудников логин Jira пуст, человек считается не работающим в Jira (руководство, бухгалтерия) и не проверяется: он попадает в раздел «не проверены», а не в ручной разбор. Если ФИО в аллокации записано иначе, чем в 1С, строка попадет в «не проверены». Исправьте написание в Excel или добавьте его в `config/employee_aliases.csv`. Файлы с ФИО и результатами сверки содержат персональные данные и в репозиторий не попадают (`out/` в `.gitignore`).

## Расчет долей из часов Jira (необязательно)

Нужен, только если в Jira ведут списания времени. Сейчас их не ведут, и этот сценарий не используется.

    pip install -r requirements.txt
    export JIRA_URL=https://jira.example.com
    export JIRA_TOKEN=...            # персональный токен, или JIRA_USER и JIRA_PASSWORD
    export JIRA_CA_BUNDLE=/path/ca.pem   # если сертификат выдан внутренним центром
    python sync_jira.py --month 2026-09 --roster config/employees.csv

Как считается доля. Для каждого, кто работал в месяце (даты найма и увольнения из 1С):

1. Если для человека задана фиксированная аллокация в `config/overrides.csv` (те, кто не списывает время: руководство, бухгалтерия, HR), берется она.
2. Иначе доля проекта = часы в проекте / все часы человека за месяц. Округление до 0,0001, сумма всегда ровно 1.
3. Если нет ни списаний, ни фиксированных долей, в отчете предупреждение, и такая строка остается без долей.

Входные файлы (формат CSV с `;`, примеры с вымышленными данными в `examples/`):

| Файл | Столбцы | Откуда |
|---|---|---|
| `config/employees.csv` | `employee_id;name;jira_login` и необязательные `position;email;hire_date;fire_date` | выгрузка из 1С |
| `config/overrides.csv` | `employee_id;project;share` и необязательные `from;to` (месяцы ГГГГ-ММ) | заполняется один раз, меняется при изменениях |
| `config/jira_project_map.csv` | `raw_name;project;weight`, `raw_name` это ключ проекта Jira | один раз, плюс слияния и разделения |

Автор списания ищется среди сотрудников по логину Jira, затем по ключу пользователя и по email. Авторы, которых нет в списке (подрядчики, уволенные), попадают в предупреждения. Часы уволенных или еще не принятых сотрудников не учитываются.

Попробовать без Jira:

    python sync_jira.py --month 2026-09 --roster examples/employees.csv --overrides examples/overrides.csv \
        --project-map examples/jira_project_map.csv --worklogs-csv examples/worklogs.csv --out out/demo --db out/demo/allocation.sqlite

`--save-worklogs файл.csv` сохраняет то, что вернула Jira, чтобы можно было проверить исходные часы или пересчитать месяц без обращения к серверу. Повторный запуск за тот же месяц заменяет его в базе, остальные месяцы не трогает. Токен читается только из переменных окружения.

Если после запуска в `out/sync/report.md` есть ошибки, проверьте соответствие проектов Jira и проектов аллокации в `config/jira_project_map.csv`.

## Где запускать и как проверить доступ

Jira доступна только через VPN, поэтому скрипты запускаются на рабочей машине с включенным VPN (или на внутреннем сервере по расписанию). Данные никуда за пределы контура не уходят. Нужен Python 3.10+ и `pip install -r requirements.txt`. Если с рабочей машины нет доступа к GitHub, код можно скачать архивом и перенести.

Сначала проверьте доступ:

    export JIRA_URL=https://jira.example.com
    export JIRA_TOKEN=...
    python check_jira.py --roster config/employees.csv

Скрипт покажет, есть ли подключение, сколько проектов доступно, есть ли задачи с исполнителями за прошлый месяц и сколько исполнителей найдено в списке сотрудников. Количество списаний времени выводится справочно. По умолчанию печатаются только количества, без логинов, такой вывод безопасно показывать другим. Ошибка сети или сертификата выводится понятным текстом.

## Перенос аллокации из Excel

### Запуск

    pip install -r requirements.txt
    python allocation_import.py data/allocation.xlsx --out out
    python -m unittest discover -s tests

Что появится в `out/`:

| Файл | Что внутри |
|---|---|
| `report.md` | ошибки, предупреждения, заметки с номерами строк и сводка загрузки по проектам и месяцам |
| `allocation.sqlite` | таблицы `employees`, `projects`, `employee_months`, `allocations` |
| `allocations.csv`, `employee_months.csv` | то же самое для просмотра в Excel (разделитель `;`, десятичная запятая) |
| `project_map.suggested.csv`, `employee_aliases.suggested.csv` | заготовки справочников |

### Как довести перенос до нуля ошибок

1. Запустите скрипт и откройте `out/report.md`.
2. Поправьте ошибки в исходном файле по номерам строк. Типичные: сумма долей не равна 1, повтор ФИО без пометки "дубль", текст вместо числа.
3. Справочники кладутся в `config/` и подхватываются автоматически:
   - `config/project_map.csv` (столбцы `raw_name;project;weight`): как названия из шапок соотносятся с проектами.
     Переименование и объединение: несколько строк ведут в один `project`. Разделение: одно `raw_name` на несколько `project` с весами, сумма весов 1.
     Если файл есть, любое название вне него считается ошибкой, так ничего не пропадет молча.
   - `config/employee_aliases.csv` (столбцы `alias;canonical`): разные написания одного ФИО.
     Скрипт только предлагает пары, объединяет их человек.
   Начните с копии `out/*.suggested.csv`.
4. Повторяйте запуск, пока ошибок нет. `--strict` возвращает код 1, если ошибки остались.

### Правила разбора

- Месячный блок начинается со строки, где в столбце B дата или текст вида "Июнь 2026", "май.26", "Октябрь 26". Дата считается как год и месяц: 26.03.2026 это март 2026.
- Шапка проектов: первая строка блока с названиями в столбцах E:L. Столбец A тег (`дубль`), B ФИО, C должность, D дата найма.
- Пустые ячейки, пробелы и нули означают "нет доли" и не загружаются. Допустимы `0,5`, `50%` и простые формулы вроде `=1*0.5`.
- Итоговые строки (`=SUM(...)`, "итого", "Без бэка") пропускаются.
- Строки с тегом `дубль` не загружаются, чтобы не считать человека дважды. Если доли в дубле отличаются, будет предупреждение.
- Блок "ПРОГНОЗ" помечается как `is_forecast = 1`.
- Сумма долей сотрудника за месяц должна быть 1 (допуск 0,005), иначе ошибка. Данные при этом все равно загружаются, а `employee_months.total_share` позволяет отфильтровать такие строки.
- Родительские заголовки над шапкой (например "ТПКБ" над "РКО" и "Продукты привлечения" в октябре) не читаются.
